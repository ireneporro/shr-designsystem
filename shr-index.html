SimplifyHR design system

A neutral-first, role-aware design system reference for HR operations, permissions, eSign workflows, and client-company management.

Base shared with Staffology

Inter, type scale, spacing, radius, shadows, density, and accessibility rules are shared.

SHR identity

The product uses a restrained purple accent and neutral surfaces. Color appears only when it carries meaning.

Role-aware by default

Every surface must consider HR Partner, Client, Site, Department, and Employee access.

Last updated: May 31, 2026

SHR philosophy

Neutral first

Most UI stays white, grey, and text-led. Purple is an accent, not a wash.

Permission clarity

Users should understand what they can see, edit, approve, or sign without learning internal access logic.

Operational calm

Tables, cards, and forms should feel dense enough for HR operations but calm enough for repeated daily use.

Hierarchy over decoration

Use typography, spacing, borders, and state before adding color.

Workflow memory

Activities, announcements, and signatures need clear history, ownership, and next action.

Tokens

SHR uses the same base primitives as Staffology, with a semantic layer for product roles and surfaces.

Accent

Used sparingly for active nav, primary action, focus, and selected structural highlights.

Text

Neutral-first text system. Use strong text for structure and muted text for metadata.

Surfaces

Page, cards, raised surfaces, and subtle section backgrounds.

Borders

Subtle lines define density and hierarchy without adding color noise.

Status

Six product states with dots. Status color is semantic, never decorative.

Role and audience

Role chips, entity initials, and scoped audience markers.

Data visualization

Neutral-purple-blue scale for product metrics. Do not use status colors for chart series.

Actions

Semantic action tokens keep buttons and repeated controls portable across SHR and future apps.

Roles and permissions

SHR is fundamentally role-aware. The design system needs to encode visibility, editability, approval, signature, and no-permission states.

Platform operator

HR Admin

Full platform access, company setup, users, payroll, invoices, reports, overrides.

Platform operator

HR Rep

Assigned client operations, employees, assignments, timesheets, payroll and invoices.

Platform operator

Safety Coordinator

Safety, compliance, site requirements, and documentation visibility.

Delegated access

HR Proxy

Temporary or delegated access. Cannot exceed the role being proxied.

Company-level user

Client

Company visibility, approvals, invoices, payroll summaries, and financial documents.

Client employee role

Site Manager

Site-level employees, assignments, and timesheets.

Client employee role

Department Manager

Department-level employees, assignments, and limited timesheet data.

Individual user

Employee

Own profile, assignments, timesheets, and personal documents.

Foundations

Typography

Inter for product UI, JetBrains Mono for system identifiers, EINs, money, and aligned numbers. Headings use --ls-tight (-0.05em / -0.8px at 16px).

Spacing

4px base scale. Use semantic spacing for cards, forms, sections, and page padding.

Radius

8px controls, 12px mid surfaces, 16px cards/modals/drawers, pill for chips and status.

Motion

Small state changes only. Respect reduced motion. No decorative animation.

eSign patterns

Internal users send

HR Admin, HR Rep, Safety Coordinator, and HR Proxy can upload, configure templates, send signature requests, reminders, and view dashboards.

Client-side users sign

Clients, site managers, department managers, and employees can view pending documents, sign documents, and download signed copies.

Status is explicit

Pending signature, sent reminder, completed, expired, and failed should render as StatusPill states with dot and label.

Applied recipes

Announcements table

  • Search by title or author
  • Audience chips in People column
  • StatusPill for publish state
  • Time and date in sortable column

Company profile

  • Hierarchy sidebar
  • Profile tabs
  • Read-only company fields by permission
  • EIN field with format validation

Client approvals

  • Client sees approvals, invoices, contracts
  • People and company data are mostly read-only
  • Internal settings are hidden
  • No-permission sections are not rendered
